# Private Codex source modules

- `src/core/brainstorm/codex-publication{,-guard,-prepare}.ts` — protocol 5 for retained native brainstorm page plans. Migration v276 extends the journal protocol guard on both engines. Admission and commit validate the retained canonical request, source authority, optional job claim and evidence revisions; canonical file effects and provenance use the existing coordinator and receipts. Older consumers refuse the new protocol.
- `src/core/persistence/codex-action-{schema,guard,prepare}.ts` — protocol 3 for recoverable host-owned Codex page actions. Migration 265 binds action ledger rows to prepared writes. Admission and publication check the retained job claim, input and authority identity, and source; the ordinary untrusted page preparer preserves page protections and rechecks the observed revision at commit.
- `src/core/minions/codex-action-writes.ts` — retains immutable host write authority before effects, reuses canonical action-derived request IDs, and reconciles actual receipts before further inference. Required writes exclude no-ops and quarantined commits. Shared action fixtures cover both storage engines; see `docs/development/private-codex-actions.md`.

- `scripts/private-codex-live-core.ts` — operator-run take/edge proposal, calibration, contextual synopsis and preview-bound fence-repair cases. - `scripts/private-codex-live-evaluation.ts` — bounded A/B drafts, one-question keyword benchmark with durable answer/judge replay, negative judge control, grounded claim insertion, fact-key/synopsis proposals and a single nightly judge slot. No fabricated preference, full-dataset accuracy, scheduled probe or vector-stage qualification.

Admission requires protected `setpriv`, `dash`, `unshare` and `true` executables; unsupported hosts refuse before subscription admission.

The [role development workstreams](../../development/private-codex-role-workstreams.md)
define the 21-core/18-extended split and the tiered policy contract.
`private-policy.ts` accepts explicit tier pins and enabled roles while retaining
legacy scalar identities; `private-roles.ts` assigns each role a tier.
OCR uses reasoning after a same-image live comparison; `private-pin-target.ts`
derives its legacy file/database OCR alias from that role assignment so a tiered
migration agrees with dispatch. Scalar migration behavior is unchanged.
Gateway `ChatOpts.privateRole` and direct dispatcher `role` carry trusted caller
identity. Dispatch acceptance and proposal caches bind role and complete policy;
queue/recovery bindings use the policy fingerprint for tiered configurations.
This shared foundation does not establish feature-level or live acceptance.
Updated core callers carry their own role identities, including the separate direct
`page-summary` and contextual synopsis roles. `private-role-scope.ts` fences
retained-result and publication boundaries against policy changes; synthesis
and pattern plans bind the policy that accepted them, so recovery cannot adopt
a different tiered grant. Core contract fixtures use explicit role allowlists.
